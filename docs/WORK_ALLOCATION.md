# OSCAR 实施分工与交接

日期：2026-09-30。技术依据：[工程设计 v0.4](OSCAR_VIRTUAL_CULTURE_DESIGN.md)。本文只划分责任，不改变 R1–R11、设备契约或验收标准。

## 当前安排

- **A — 3D 模型与场景升级**：由本聊天助手负责，2026-09-30 已按用户本轮要求启动并交付；详见 [场景交接](SCENE_HANDOFF.md)。
- **B — 其余系统实现**：由用户另行安排的执行代理负责。本聊天不代为启动执行代理。
- A 已交付场景模块、初始 scene-map、附加几何、素材与独立验收页；B 侧尚未提供契约或初始映射，最终 API / 页面数据集成仍由 B 完成。

## A：本聊天助手负责

把现有 OSCAR 模型升级为可承载设备状态与动作的 3D 场景，覆盖工程设计 §8.2 和 P1 中的场景部分。

| 工作 | 交付内容 |
| --- | --- |
| 模型与素材整理 | 按需要调整 Blender 母模型、生成脚本、GLB、材质及贴图，保持可复现的资产制作路径 |
| 模型节点与坐标映射 | 工位、板孔、移液头节点及坐标转换；升级模型时同步维护 scene-map |
| 场景渲染改造 | 提取现有 `web/app.js` 的 Three.js 场景逻辑；受控工位在静态合并前排除，保留拾取与动画所需节点 |
| 动作呈现 | 排枪整排同步移液示意（按 2026-09-30 用户补充）、待机与受控动画切换、基于状态的阶段插值、暂停和恢复显示 |
| 新增示意部件 | 随移液头的虚拟相机、原工位 shake 载台、液位及针尖光效覆盖层 |
| 场景交互 | 外观/内部切换、聚焦设备或板孔、3D 拾取与高亮；将选中结果交给操作台 |
| 场景验证 | 模型节点、坐标、板孔编号、动作显示、材质与视觉检查；模型修改后按需执行 Blender 验证 |

主要负责路径：`OSCAR_master.blend`、`models/`、`source/` 中的资产制作与验证脚本、`textures/`、模型预览产物，以及 `web/scene/`。本轮 A 在这些路径交付可复现的运行时附加几何与材质，保留原 GLB 和母模型。

A 接收 Runtime 已确认的状态与事件，呈现动作；不根据动画结束回写库存、液量、动作成功或模拟时间。场景相机和视觉效果不生成 Agent 的权威观测证据。

## 交接边界

### 1. P0 可独立推进

B 使用当前 `models/OSCAR_full.glb` 和设计 §8.2 的已确认工位分配，在 P0 创建初始 `web/scene/scene-map.json`，只记录现有节点、板型和孔位坐标，不重导出 GLB，也不改 `batchStatic()`。节点存在性和孔数契约测试由 B 编写并接入统一测试命令。

本轮 B 尚未提供初始映射，A 已按已确认工位建立该文件及独立契约测试；B 可直接接入统一测试。A 接管该文件的模型侧维护。后续每次模型升级，A 同步更新映射并运行 B 提供的契约测试。逻辑 `device_id / plate_id / well_id` 与场景节点名分别管理；模型重导出不能悄悄改变业务 ID。

### 2. 状态与事件由 B 提供，场景由 A 呈现

B 负责设备协议、客户端和事件恢复，向场景交付：

- 当前 Experiment 身份、模拟时刻、暂停状态和相关资源状态。
- 板孔液量、shake 状态、活动动作的阶段、目标、阶段起始时间与持续时间。
- 已去重并按序处理的设备事件，以及重连或切换 Experiment 后的完整状态快照。

A 的场景模块接收这些数据，负责定位、插值和覆盖层；向 B 返回用户选中的板孔等交互结果。具体场景调用接口在 B 的契约和 A 的模块提取交接时确定，本次不另造一套设备 API。

SSE 重连、身份认证和请求重试留在 B 的适配层；场景模块不直接持有服务端凭证。回放时仍由 B 提供历史状态，A 只读呈现。

### 3. 现有前端入口的改动顺序

当前 `web/app.js` 将渲染与交互放在同一文件，容易发生重叠修改：

1. B 在 P0 可以补齐依赖、搭建服务和新增 API/面板模块，保留现有场景逻辑。
2. A 开始后把模型加载、`batchStatic()`、摄像机、动画与拾取迁入 `web/scene/`，交付可挂载、更新和销毁的场景模块。
3. B 接入页面入口、业务控件和数据流。最终页面组合与全局样式由 B 维护，场景内部实现由 A 维护。

交接完成前不同时重写 `web/app.js`。若 B 先推进 P1，可先做业务面板和场景容器，沿用现有预览作为占位，不提前改造 A 负责的模型与渲染逻辑。

### 4. 验收责任

设计 §9 仍为统一验收标准。B 负责系统测试和最终集成验收；A 负责模型、场景动画与视觉问题的验证及修复。P0 的状态闭环与确定性测试不依赖 3D 升级完成；P1 的完整演示需要 A/B 两部分交付共同通过。

模型贴图与预览资产的缺项由 A 在资产工作中处理；运行时 Three.js 依赖由 B 在 P0 处理。服务端扫描 PNG 属于 B，不与模型贴图或浏览器截图混用。
