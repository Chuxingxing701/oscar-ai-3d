# 升降跳变修复（2026-09-30）

原因：Runtime 升降阶段为 1 个模拟秒。原 PresentationClock 在下一阶段到达时把显示时间下限夹到新阶段起点，场景又始终使用最新阶段，因此下降起点之后直接显示吸液低位，抬升起点之后直接显示横移高位。之前仅检查横移/振荡的逐帧更新，没有覆盖跨阶段的一秒升降。

修改：

- scene-adapter 传入 action_id；PresentationClock 保存同一动作已收到的短阶段历史，并按插值后的显示时间选阶段，不跳过尚未显示完的升降。
- 显示时间仍不超过服务器已确认时间。液体/库存来自最新提交快照，不进行动画推算；没有改变 Runtime 时长或推进方式。
- 缺失阶段、动作替换、取消、暂停/回放、倒放或换实验清理历史并准确定位，不继续播放旧动作。
- 取头/弃头原语没有单独的升降子阶段，增加阶段内平滑的下降—抬升示意，两端都回到高位。

验证：

- npm run typecheck 通过。
- 定向 Node 测试 29/29（展示时钟、适配器、真实 GLB 场景与碰撞/扫描光效回归）。
- 定向真实进程 + Chromium 测试 2/2：原连续运动/振荡/扫描测试，以及新增 vertical-motion 用例。
- 新用例提交真实 media.add，先推进到下降/抬升起点，再推进一个模拟秒至下一阶段，捕获 RAF 中间位姿，验证 0 至 −0.12 m 的过渡、升降途中 X/Z 不横移、显示时间不超前于 Runtime，以及最终端点正确。
