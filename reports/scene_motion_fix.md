# 操作台动画修复（2026-09-30）

处理用户反馈：摇床不动、加液/换液跳帧、扫描未对准选中的培养板。

## 原因与修改

1. Runtime 先发送包含完整时长、转速、revision 的 `plate.shake_started`，随后发送仅用于记账的 `action.effect_committed`。前端重复用后者覆盖振荡状态，将时长改成 0，且重复增加 revision。现只用 plate 事件投影运动参数，revision 使用服务器值。
2. 服务器以整数模拟秒推进，原场景只在新快照到达时计算位姿。移液因此按秒跳动；4 Hz 振荡在整数秒采样又恰好总回到原位。新增 `PresentationClock`，由 RAF 在最近已确认的时间区间逐帧采样，不预测未来模拟时刻。相同时间的重复时钟帧不重启插值。暂停/回放/倒放/换实验精确定位，断线后补完已确认区间即停止。无动作且无振荡时不持续插值重绘。
3. 点击场景/孔位列表只移动了观看视角，没有同步扫描表单，实际请求可能仍为默认的 plate-01。扫描表单现跟随新板孔选择，明确显示待提交目标；手动改变下拉选择后，不被后续状态刷新覆盖。切换扫描板立即重建孔位列表。真实 GLB 核验显示：原镜头/光锥在扫描阶段的坐标本来就是对齐的；本次补全 camera 工具在升降阶段的定位，并添加两块板所有 48 孔的镜头/光锥对齐回归。

液量与库存始终显示 Runtime 已提交状态。逐帧更新只动机械、光效和振荡，不重写液体矩阵，不生成观测，不把动画当设备执行证据。

## 使用

刷新操作台即可加载新版前端，无需重新配对或重启 Runtime。人工连续观看请选 `realtime`，先用 1×；`lockstep` 提交后需单步推进，`推进至空闲` 本来就是直接完成动作，不播放完整过程。操作区已加相应提示。Agent 继续使用 lockstep，由 Agent 释放屏障后驱动模拟时钟。
