# 扫描出发及归位瞬移跟进（2026-09-30）

用户第二段 16.31 秒录屏显示扫描移动和归位有跳变。排查发现，`PresentationClock` 将首次出现的 action 当成必须立即定位的切换，跳过了第一个已确认时间区间；当 Runtime 完成归位、释放 head 时，场景又因 `actions=[]` 关闭插值，丢弃最后一个已确认移动区间。

## 修复

- 首次 action 从上一次已确认的空闲时间平滑进入移动。
- 成功归位后，只在显示时间尚未到达归位结束时保留该移动阶段，走完后回到无动作状态；后续从 home 出发的新动作可以连续衔接。
- 暂停、回放、重置、后退、中途取消及未知阶段缺口仍立即定位；不推演未来步骤，不修改 Runtime 的动作、效果或库存。
- 场景在释放 head 后保留必要的归位插值；彻底空闲时仍不持续绘制无变化的机械臂。

## 验证

新增纯时间测试先在旧代码上失败：首次 action 的显示时间直接从 0 跳到 1 秒，随后验证归位结束后的最后半秒和空闲后再次出发。

- `node --test tests/web/*.test.mjs web/scene/tests/scene.test.mjs`：**51/51 通过**，包含原有升降、扫描对准、暂停、回放、取消和碰撞抽样。
- `npm run typecheck`：通过。
- 桌面布局两项 e2e：通过，完整 scripted 扫描、整排换液、shake、复查仍完成且场景尺寸稳定。
- 真实扫描边界 e2e：以 speed 1、realtime 依次扫描 `plate-02/D6` 和 `plate-01/A1`，逐 RAF 检查移动距离与帧间时间的上界，出发和归位两段都有中间位置，结束回到原待命位，场景没有投影错误。

验收过程曾因软件渲染只采到 16 个不同位置而未达到测试最初的固定“20 帧”阈值。该阈值受机器帧率影响，已改为分别验证出发和归位两段的中间位置；逐帧连续性上界、完成状态、最终待命位置及投影错误检查均保留。没有修改生产代码来规避测试。

此轮未重跑全量系统测试。测试在独立临时数据目录运行，未操作用户当前实验；刷新当前操作台页面加载新模块即可。
